Please use the following template when submitting a change request. Provide sufficient information for reviewers to understand the purpose, scope, dependencies, and potential impact of your proposal.

## Submission Guidelines

- Check existing discussions and requests before submitting a new proposal to avoid duplication.
- Provide sufficient technical and operational details for a meaningful review.
- Keep the proposed scope clear and specific.
- Clearly identify any dependencies or potential impacts.
- Be prepared to provide additional clarification during the review process.
- Do not begin implementation before receiving explicit approval through the NAV Change Board.
- Pull Requests submitted without prior change approval will not be accepted.
- Any significant deviation from the approved scope must be discussed and approved before proceeding.

> [!IMPORTANT]
> **Submitting a change request does not constitute approval for implementation.**
>
> Change requests must receive explicit approval through the NAV Change Board before development begins.
>
> Approval of a change request does not guarantee approval or merging of the resulting Pull Request.

## Change Request Lifecycle

**Discord Submission → Discussion → Approval → Implementation → GitHub Pull Request → Technical Review → Merge**

The Discord review determines whether the proposed change should be implemented.

The GitHub review determines whether the approved change has been implemented correctly and meets the repository's technical requirements.

Both stages are mandatory.
